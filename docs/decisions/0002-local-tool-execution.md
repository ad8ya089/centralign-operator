# ADR 0002 — Transactional local tools, literal search, and restricted browsing

Date: 2026-10-25. Status: Accepted for Phase 2.

Keep the existing SQLite execution ledger as the idempotency authority instead of adding a second action cache. Canonical validated input is recursively key-sorted and hashed. A write key is globally unique and bound to tool, run, step, actor, and argument hash. The immediate SQLite transaction checks that identity, writes business state, and commits its validated result and audit events together. The database uniqueness constraint is the final duplicate boundary, including independent processes. Reads use fresh generated ledger keys. No autonomous retry is introduced.

Synchronous local writes avoid holding a SQLite transaction across await. Async write handlers are rejected; read handlers may be async and cooperatively cancelled. Budgets use a context deadline, per-tool timeout, and elapsed wall time. A synchronous native call cannot be forcibly interrupted by JavaScript; SQLite busy timeout bounds lock waiting, and a late local transaction is rolled back after control returns. General external exactly-once execution is not claimed.

Filesystem writes cannot participate in SQLite atomic commits. Use deterministic, key-owned run/execution subdirectories, exclusive file creation, ancestor/link checks, byte hashing and fsync. A post-file/pre-database failure records UNKNOWN_OUTCOME. Reconciliation can adopt only existing matching owned bytes and reconstruct the metadata/result; it never blindly recreates an unknown file. Conflicting or missing bytes remain blocked. This is deliberately narrower than a general distributed transaction protocol. Concurrent hostile directory replacement by another OS process is outside the local prototype's filesystem trust model; containment checks do not replace an OS sandbox.

Prefer FTS5 over three Markdown sources when actually available (the tested SQLite 3.53.4 supports it). Optional FTS DDL is part of migration 2, with deterministic relational text search when unavailable. Literal token quoting and bound parameters prevent caller-controlled MATCH syntax. This avoids embeddings, service dependencies, and duplicating whole documents in every search response. Fallback uses substring matching and stable ordering; it does not provide BM25 relevance or identical tokenization.

The restricted browser uses Playwright with ephemeral contexts, JavaScript disabled, service workers blocked, no downloads or stored credentials, and denied subresources. Trusted fetch code follows redirects manually, validating every hop before requesting it and streaming under a byte limit; the browser receives only permitted readable content. Browser navigation's own resulting URL is also revalidated. A configured origin is a server trust decision, never a model argument. Default is deny. This adapter offers open/snapshot only, not an interactive browser agent or arbitrary evaluation surface.

Persisted exact-action approval is checked in the common execution wrapper and email handler before sandbox effects. Real delivery remains absent; an outbox record means SANDBOX_QUEUED, not delivered. Approval issuance/identity/UI are future work. Phase 3 must use the executor rather than invoke handlers directly.
